# 連署後端設定指南（Google 試算表＋Apps Script）

這份文件寫給負責維護連署資料的同事，不需要寫程式，照著四個步驟做完即可。全程請用 GCAA 的 Google 帳號操作，避免日後交接時資料留在個人帳號裡。

網站的資料來自兩份試算表：一份是工作人員手動維護的「候選人簽署」試算表，記錄六都候選人的簽署狀態；另一份是連署 Google 表單自動產生的回覆試算表，裡面是團體與個人的連署紀錄。前者要開放檢視，後者因為含有 Email，必須維持不公開，只透過 Apps Script 把可公開的部分交給網站。

做完之後會得到兩樣東西：候選人簽署試算表的編號（SHEET_ID），以及一個網頁應用程式網址。把這兩樣交給網站維護者，網站就會開始讀取真實資料；在那之前，網站會顯示示意資料。

---

## 步驟一：準備兩份試算表

### 候選人簽署試算表

這份試算表已於 2026 年 9 月 3 日用 GCAA 帳號建好，名稱是「2026 六都市長候選人簽署狀態（網站資料來源）」，網址：https://docs.google.com/spreadsheets/d/18MZP1jPFbK7Orn_W-66r-LjVsIpFIt1GkYwSlfvS_GY/edit 。標題列、縣市與狀態的下拉選單、十八個訴求的勾選框都已設定好，協作者直接填寫即可；請把需要填寫的同事加為編輯者。裡面只有一個工作表，名稱必須維持完全一致（不要有空白、不要用簡體字），因為程式是照名稱去找資料的：

- 候選人簽署

第一列是欄位標題列，程式讀取時會跳過第一列。欄位順序不可調換，也不要在中間插入新欄位；如果日後要加欄位，請加在最後面，並先告知網站維護者。

依序共 24 欄：

| 欄位順序 | 欄位標題 | 填寫說明 |
| --- | --- | --- |
| 1 | 縣市 | 臺北市、新北市、桃園市、臺中市、臺南市、高雄市 |
| 2 | 姓名 | 候選人姓名 |
| 3 | 政黨 | 政黨全稱，無黨籍請填「無黨籍」 |
| 4 | 狀態 | 只能填「已簽署」「部分簽署」「未回應」三者之一 |
| 5～22 | 訴求1～訴求18 | 該候選人承諾的訴求打勾，未承諾留空（勾選框；填「1」或「是」也可以） |
| 23 | 簽署日期 | 格式 2026/09/15 |
| 24 | 照片URL | 候選人照片的公開圖片網址，沒有就留空 |

第 5 到第 22 欄的標題請照順序打成「訴求1」「訴求2」……一直到「訴求18」。這 18 欄是五大面向的訴求依序展平，對應關係如下：

| 欄位 | 所屬面向 |
| --- | --- |
| 訴求1～訴求3 | 一、再生能源與產業永續轉型 |
| 訴求4～訴求6 | 二、防災韌性與民生保障 |
| 訴求7～訴求10 | 三、高溫調適與健康安全 |
| 訴求11～訴求13 | 四、水患治理轉型 |
| 訴求14～訴求18 | 五、永續交通轉型 |

各項訴求的完整文字以網站上呈現的版本為準，填表時只要對照序號打勾即可。

### 連署表單的回覆試算表

這一份不用自己建。在連署 Google 表單的「回覆」分頁點「連結至試算表」之後，Google 會自動產生一份試算表，工作表名稱是「表單回覆 1」，欄位順序跟表單題目順序一致。

有三件事請不要做：不要改工作表名稱、不要調換欄位順序、不要刪掉整欄。程式是照名稱找工作表、照欄位位置讀資料的，動了其中一項網站就會讀不到。表單題目本身若要修改文字沒有關係，但若要新增或刪除題目，請先告知網站維護者。

如果有團體不是透過表單連署（例如承辦人直接邀請到的），或某個團體自己填的名稱不適合直接顯示（例如填了簡稱、有錯字），有兩個做法：

- 直接修改「表單回覆 1」裡那一列的「團體名稱」欄，改成要顯示的名稱。這不會影響其他資料。
- 另外新增一個工作表，名稱要完全等於「團體補登」，A 欄一列一個團體名稱（第一列可以放標題「團體名稱」，也可以直接從第一列開始填）。程式會把這裡的名單接在表單來的名單後面。同一個團體若在表單和補登都出現，只會算一次，並以補登的寫法顯示：比對時會忽略空白與臺／台的差異，名稱一個包含另一個就視為同一團體，例如表單填「TRENA 台灣再生能源推動聯盟」、補登填「台灣再生能源推動聯盟」，網站只顯示後者。

沒有建「團體補登」這個工作表也沒關係，程式會自動略過。

### 關於個資

回覆試算表裡有連署人的 Email、職業、對行動的疑問與建議，這些都不會出現在網站上。網站只會拿到三樣東西：團體名單、個人連署的總人數，以及那些在「是否同意公開連署理由」選了「同意公開」的個人留言。留言旁邊要顯示什麼名字，是照連署人自己在「希望我們公開哪些連署資訊」的選擇決定的：選了公開姓名的，顯示成「林○安」這種遮住第二個字的形式；選擇只計入人數的，一律顯示「連署公民」。

因此這份回覆試算表請維持只有工作人員能存取，絕對不要開放連結分享。

## 步驟二：設定分享權限並取得 SHEET_ID

兩份試算表的處理方式相反，請不要弄混。

**候選人簽署試算表要開放檢視**，因為網站是直接讀它的內容：

1. 打開試算表，點右上角「共用」。
2. 在「一般存取權」把「限制」改成「知道連結的任何人」。
3. 右邊的角色務必維持「檢視者」，不要選「編輯者」或「加註者」。
4. 按「完成」。

接著從網址列抄下 SHEET_ID。試算表網址長這樣：

```
https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890/edit#gid=0
```

其中 `/d/` 與 `/edit` 之間那一長串（上例的 `1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890`）就是 SHEET_ID，把它複製下來備用。這個值最後要交給網站維護者。

**回覆試算表維持不公開**，「一般存取權」請留在「受限制」，只有工作人員看得到。它的網址一樣有一長串編號，用同樣方法抄下來，但這一個不是交給網站維護者，而是步驟三要貼進 Apps Script 程式碼裡的。網站永遠不會直接碰到這份試算表，只會透過 Apps Script 拿到整理過的結果。

## 步驟三：建立 Apps Script 專案並部署

1. 到 [script.google.com](https://script.google.com/)，確認左上角登入的是 GCAA 帳號，點「新增專案」。
2. 專案名稱改成「六都倡議連署後端」之類容易辨認的名字。
3. 編輯區預設會有一段 `function myFunction() {}`，把它整段刪掉。
4. 打開專案原始碼裡的 `apps-script/Code.gs`，把整份內容複製貼上到編輯區。
5. 找到第一行 `const SHEET_ID = 'PUT_SHEET_ID_HERE';`，把 `PUT_SHEET_ID_HERE` 換成**回覆試算表**的編號（不是候選人簽署那一份），引號要留著。
6. 按上方的儲存圖示（或 Ctrl+S／Cmd+S）。
7. 點右上角「部署」→「新增部署作業」。
8. 左邊齒輪的「選取類型」選「網頁應用程式」。
9. 「執行身分」選「我」。這樣腳本才有權限讀那份不公開的回覆試算表。
10. 「誰可以存取」選「任何人」。這一項若選錯，網站會讀不到連署資料。
11. 按「部署」。第一次部署會跳出授權畫面：選 GCAA 帳號，出現「Google 尚未驗證這個應用程式」時，點「進階」→「前往（專案名稱）（不安全）」→「允許」。這是自行撰寫的腳本存取自己試算表的正常流程。
12. 部署完成後會出現一段「網頁應用程式」網址，格式是 `https://script.google.com/macros/s/.../exec`，點「複製」把它存下來。

網站只會用讀取的方式（GET）呼叫這個網址，不會往回寫任何東西，所以連署資料只能從 Google 表單進來。

日後如果修改了程式碼，要再點一次「部署」→「管理部署作業」→編輯現有部署→版本選「新版本」→「部署」，網址才會指向新的程式碼。若改成「新增部署作業」，網址會變，網站就要跟著更新。

---

## 步驟四：交給網站維護者

把兩樣東西一起交出去：

- 候選人簽署試算表的 SHEET_ID
- 步驟三複製的網頁應用程式網址

網站維護者會填進 `src/data/config.ts` 這個檔案的 `SHEET_ID` 與 `APPS_SCRIPT_URL`，重新建置並部署網站。

這兩個值填好之前，網站是這樣運作的：簽署看板顯示標著「示意資料」的假候選人；連署團體則顯示網站內建的已確認名單，也就是 2026 年 9 月 3 日確認的六個團體。網址填好之後，團體名單就會改成表單回覆試算表裡的即時資料。

部署完成後請做一次實測：用連署 Google 表單自己送出一筆團體連署，回到網站重新整理，看團體數字與名單有沒有多出這一筆；確認無誤後，回到回覆試算表把這筆測試資料整列刪掉。
